# ShellLayout

The complete application frame: menu bar, activity bar, sidebar, a
`flexlayout-react` docking area, terminal, chat pane and status bar.

## How it differs from the primitives

Every component `ShellLayout` renders is also exported on its own, in a pure,
prop-driven form. `ShellLayout` is the assembled version: it writes the props
you pass into a set of zustand stores on mount, then renders the `Connected*`
variants that read from those stores.

That indirection buys one thing — plugins and distant code can contribute menu
items, status bar widgets and sidebar panels without the shell knowing about
them, and without prop-drilling through your component tree.

It costs the usual price of global state: two shells on one page share it. If
that matters, compose the primitives yourself.

## Configuration flows through registries

Three registries decouple the shell from what it renders:

| Registry | What it holds | Referenced by |
| :-- | :-- | :-- |
| `componentRegistry` | React components, by id | `component` on a layout model tab |
| `commandRegistry` | Executable commands, by id | `commandId` on menu and status bar items |
| `menuRegistry` | Menu structure | Populated from `menuConfig` |

So a tab in your layout model names a component id, not an import:

```tsx
componentRegistry.register('editor', Editor);

Model.fromJson({
  layout: {
    type: 'row',
    children: [{
      type: 'tabset',
      children: [{ type: 'tab', name: 'App.tsx', component: 'editor' }],
    }],
  },
});
```

And a menu item names a command id, not a function:

```tsx
commandRegistry.registerCommand({
  id: 'file.save',
  label: 'File: Save',
  keybinding: '⌘S',
  execute: () => save(),
});

<ShellLayout menuConfig={{ File: [{ id: 'save', label: 'Save', commandId: 'file.save' }] }} />;
```

## Controlled vs. persisted layout

By default the docking model lives in `useLayoutStore` and persists across
reloads. Passing `layoutModel` takes control: the shell renders your model and
stops writing changes back to the store.

The stories on this page all pass `layoutModel` so each renders a clean layout
rather than inheriting the last one you dragged.

## Dirty tabs

Mark a tab dirty and closing it prompts first:

```tsx
useLayoutStore.getState().setTabDirty(tabId, true);
```

The confirmation goes through `useModalStore`, so mount `<ConnectedModal />`
near your root for the prompt to appear.

## Full example

<Canvas of={ShellLayoutStories.Branded} />

```tsx
import { Files, GitBranch } from 'lucide-react';
import { ShellLayout, ThemeSwitcher, componentRegistry } from 'nexus-shell';

componentRegistry.register('editor', Editor);

export const App = () => {
  const [theme, setTheme] = useState('light');

  return (
    <ShellLayout
      title={<Logo />}
      rightMenuBarContent={<ThemeSwitcher value={theme} onChange={setTheme} />}
      panels={[
        { id: 'files', label: 'Explorer', icon: Files, component: FileExplorer },
      ]}
      menuConfig={{
        File: [{ id: 'save', label: 'Save', commandId: 'file.save' }],
      }}
      statusBarConfig={[
        { id: 'branch', label: 'main', icon: GitBranch, alignment: 'left' },
      ]}
      slashCommands={[
        { command: 'clear', description: 'Clear the chat', execute: () => clear() },
      ]}
    />
  );
};
```
