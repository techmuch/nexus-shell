# Getting Started

From an empty directory to a working IDE-style application, then growing it.

## 1. Install

```bash
npm install nexus-shell
npm install react@^19 react-dom@^19
```

Import the stylesheet once, in your entry file. It defines the design tokens
every component reads — without it, everything renders unstyled.

```ts
// main.tsx
import 'nexus-shell/style.css';
```

If your app uses Tailwind, add the package to your `content` globs so classes
used inside the library aren't purged:

```js
// tailwind.config.js
export default {
  content: ['./src/**/*.{ts,tsx}', './node_modules/nexus-shell/dist/**/*.js'],
};
```

## 2. Apply a theme

Colors live on CSS custom properties scoped to a theme class, so switching
themes is a class on an ancestor — no context, no provider.

```html
<html class="theme-dark">
```

## 3. Render the shell

This is a complete application.

```tsx
// main.tsx
import { createRoot } from 'react-dom/client';
import { Boxes, Files } from 'lucide-react';
import {
  AppTitle,
  ShellLayout,
  componentRegistry,
  initializeShell,
  useLayoutStore,
} from 'nexus-shell';
import 'nexus-shell/style.css';

import { Editor } from './Editor';
import { FileExplorer } from './FileExplorer';

// Views are registered by id, so the shell never imports them.
componentRegistry.register('editor', Editor);

initializeShell({
  panels: [{ id: 'files', label: 'Explorer', icon: Files, component: FileExplorer }],
  commands: [
    {
      id: 'file.save',
      label: 'File: Save',
      keybinding: 'Control+s',
      execute: () => save(),
    },
  ],
  menus: {
    File: [{ id: 'save', label: 'Save', commandId: 'file.save' }],
  },
  statusBar: [{ id: 'branch', label: 'main', alignment: 'left' }],
});

// Open something on startup.
useLayoutStore.getState().addTab('editor', 'App.tsx');

createRoot(document.getElementById('root')!).render(
  <ShellLayout title={<AppTitle title="Acme Studio" icon={<Boxes size={16} />} />} />,
);
```

You now have dockable tabs, a working command palette on `Cmd/Ctrl+Shift+P`, a
terminal, a chat pane, and a themable frame.

`initializeShell` also registers a small set of built-in commands — toggle
terminal, toggle chat, toggle sidebar, and one per bundled theme — along with a
default **View** menu. Pass `defaultCommands: false` to own every id yourself.

## 4. Grow it

Add capability by registering it. None of these change the layout.

### A new view

```ts
componentRegistry.register('settings', SettingsView);
useLayoutStore.getState().addTab('settings', 'Settings');
```

### An action, with a hotkey and a menu entry

```ts
commandRegistry.registerCommand({
  id: 'git.commit',
  label: 'Git: Commit',
  keybinding: 'Control+Enter',
  execute: () => commit(),
});

menuRegistry.registerMenu('Git', {
  id: 'git.commit',
  label: 'Commit',
  commandId: 'git.commit',
});
```

Registered commands appear in the command palette automatically.

### A status bar item, from anywhere

```ts
useStatusBarStore.getState().addWidget({
  id: 'lint',
  label: '0 problems',
  alignment: 'left',
  commandId: 'view.problems',
});
```

### A dialog, from outside React

```ts
const confirmed = await useModalStore.getState().openConfirm('Discard changes?');
```

### An unsaved-changes guard

```ts
useLayoutStore.getState().setTabDirty(tabId, true);
```

Closing that tab now prompts before discarding it.

## 5. When you need less than the shell

Every component the shell is built from is exported on its own, pure and
prop-driven. Reach for them when you are embedding one piece into an app you
already have, or need a frame `ShellLayout` can't express.

```tsx
import { ActivityBar, SidebarPane, StatusBar, TreeWidget } from 'nexus-shell';

const [active, setActive] = useState<string | null>('files');

<div className="theme-dark flex h-screen flex-col">
  <div className="flex flex-1">
    <ActivityBar
      items={panels}
      activeId={active}
      onSelect={(id) => setActive(id === active ? null : id)}
    />
    {active && (
      <SidebarPane title="Explorer" onClose={() => setActive(null)}>
        <TreeWidget data={files} onToggle={toggle} />
      </SidebarPane>
    )}
    <main className="flex-1">{children}</main>
  </div>
  <StatusBar widgets={[{ id: 'branch', label: 'main', alignment: 'left' }]} />
</div>;
```

These components are controlled, so state stays in your app. That is a real
cost — the shell manages this state for you — which is why this is the fallback
rather than the default.

### The one gotcha

`TreeWidget` renders expansion from each node's `isOpen` but does not own it, so
your file data stays the single source of truth. You write the toggle:

```ts
const toggle = (items: ITreeNode[], id: string): ITreeNode[] =>
  items.map((node) =>
    node.id === id
      ? { ...node, isOpen: !node.isOpen }
      : { ...node, children: node.children && toggle(node.children, id) },
  );
```

## 6. Mixing the two

The `Connected*` components are exported, so you can rearrange the shell's own
parts while keeping its behaviour:

```tsx
import { ConnectedActivityBar, ConnectedStatusBar } from 'nexus-shell';

<div className="theme-dark flex h-screen flex-col">
  <div className="flex flex-1">
    <ConnectedActivityBar />
    <YourOwnSidebar />
    <main className="flex-1">{children}</main>
  </div>
  <ConnectedStatusBar />
</div>;
```

These read the same stores `initializeShell` populates, so registrations keep
working.
